## 2. 部署调度中心

### 2.1 建表

执行 `scheduler-admin/src/main/resources/db/scheduled-schema.sql`（四张表：`sched_task`/`sched_executor`/`sched_task_log`/`sched_leader`，其中 `sched_leader` 仅 HA 启用时使用），或设 `auto-ddl=true` 启动自动建表。

### 2.2 配置

```yaml
server:
  port: 8080
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/scheduler?useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: root
scheduler:
  admin:
    enabled: true
    pool-size: 8                 # 触发线程池
    table-name: sched_task
    auto-ddl: true
    access-token: ${SCHED_TOKEN:changeme}   # 与执行器共享
    heartbeat-timeout: 90        # 秒，心跳超时剔除
    reaper-interval: 30          # 秒，剔除扫描周期
    trigger-timeout: 5000        # ms，HTTP 触发超时
    min-period-ms: 1000
    management-auth-enabled: true            # 管理 API 令牌鉴权，生产保持 true
    management-token: ${SCHED_MGMT_TOKEN:}   # 管理 API 专用令牌；为空回退 access-token
    ha-enabled: false            # 多 admin 主备时 true（须共享同一 DB）
    election-interval: 10        # 秒，选主/续约周期
    leader-timeout: 30           # 秒，leader 心跳超时允许接管
```

### 2.3 启动

`java -jar scheduler-admin.jar`（默认内嵌 H2，端口 8080）。控制台为独立工程 `scheduler-console`：开发态 `npm run dev`（端口 5173，`/api` 代理到 8080，令牌经 `VITE_SCHED_TOKEN` 注入）；生产 `npm run build` 后将 `dist` 交由 Nginx 等托管并反代 `/api` 到 admin。

## 3. 业务服务接入执行器 SDK

### 3.1 复制 SDK

将 `com.common.schedule.executor` 包 + 注册文件复制到业务服务：

```
src/main/java/com/common/schedule/executor/**
src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
```

> 可整体重命名基础包，同步改注册文件类名。SDK 无业务耦合、不依赖数据库。

### 3.2 引入依赖

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
</dependency>
<!-- SDK 内部用 RestTemplate 通信，无需额外依赖 -->
```

### 3.3 配置执行器

```yaml
scheduler:
  executor:
    enabled: true
    app-name: order-service                       # 服务唯一标识
    admin-addresses: http://scheduler-admin:8080  # 调度中心地址（可多个逗号分隔）
    port: 9999                                    # 执行器端点端口
    access-token: ${SCHED_TOKEN:changeme}         # 与 admin 一致
    heartbeat-interval: 30
```

### 3.4 加注解

```java
@Component
public class OrderTask {
    @ManagedScheduled(name="订单超时关闭", group="order",
        description="关闭超时未支付订单", cron="0 */5 * * * ?",
        route=RouteStrategy.FAILOVER)
    public void closeTimeout() { /* 业务逻辑 */ }
}
```

启动业务服务 → 执行器扫描注册到 admin → 控制台出现任务 → 按 cron 触发。**改周期/启停在控制台操作，业务服务无需重启。**

## 4. 注解与路由示例

### 4.1 固定频率 + 轮询
```java
@ManagedScheduled(name="库存同步", type=ScheduleType.FIXED_RATE,
    fixedRate=30000, initialDelay=5000, route=RouteStrategy.ROUND, block=BlockStrategy.DISCARD)
public void pullStock() { ... }
```

### 4.2 固定延迟
```java
@ManagedScheduled(name="缓存清理", type=ScheduleType.FIXED_DELAY,
    fixedDelay=120000, route=RouteStrategy.RANDOM)
public void expireCache() { ... }
```

### 4.3 分片广播（集群并行批处理）
```java
@ManagedScheduled(name="用户画像批处理", cron="0 0 2 * * ?",
    route=RouteStrategy.SHARDING_BROADCAST)
public void userProfile() {
    int idx = ShardingContext.getShardIndex();
    int total = ShardingContext.getShardTotal();
    // 处理 id % total == idx 的数据，各实例并行不重叠
}
```

### 4.4 默认停止
```java
@ManagedScheduled(name="推送补偿", cron="0 0 * * * ?", enabled=false)
public void pushMessage() { ... }
```

> 方法须 public 无参；分片信息通过 `ShardingContext`（ThreadLocal）获取。建议方法幂等。

### 4.5 路由策略选择建议

| 场景 | 推荐策略 |
|---|---|
| 集群单跑、要求高可用 | FAILOVER |
| 集群单跑、简单 | FIRST / ROUND |
| 大数据量并行批处理 | SHARDING_BROADCAST |
| 固定打到某台 | CONSISTENT_HASH |

## 5. 控制台 API 调用

基址 `/api`，响应 `{code,message,data}`。管理 API 须携带 `X-Access-Token`（与 `management-token`/`access-token` 一致）；写操作携带 `?version=`（取自任务视图，乐观锁）。

```bash
TOKEN=changeme
# 列表 + 服务端过滤（appName/keyword/group/enabled 均可选）
curl -H "X-Access-Token: $TOKEN" "/api/tasks?appName=order-service&enabled=true&group=order"
# 改周期（version 来自 GET 详情/列表）
curl -X PUT -H "X-Access-Token: $TOKEN" "/api/tasks/order-service:orderTask.closeTimeout/schedule?version=0" \
  -H "Content-Type: application/json" -d '{"type":"CRON","cron":"0 */1 * * * ?"}'
curl -X PUT -H "X-Access-Token: $TOKEN" "/api/tasks/{id}/route?version=1" \
  -H "Content-Type: application/json" -d '{"routeStrategy":"SHARDING_BROADCAST","blockStrategy":"SERIAL","retryCount":1}'
curl -X POST -H "X-Access-Token: $TOKEN" "/api/tasks/{id}/stop?version=2"
curl -X POST -H "X-Access-Token: $TOKEN" "/api/tasks/{id}/start?version=3"
curl -X POST -H "X-Access-Token: $TOKEN" "/api/tasks/{id}/trigger"   # 触发无需 version
curl -H "X-Access-Token: $TOKEN" "/api/executors?appName=order-service"
curl -H "X-Access-Token: $TOKEN" "/api/tasks/{id}/logs?limit=50"
```

## 6. 前端 Vue3 控制台

依赖：`vue@3`、`element-plus`、`axios`。

### 6.1 API 封装 `src/api/scheduler.js`

```js
import axios from 'axios'
const http = axios.create({ baseURL: '/api', timeout: 10000 })
// 管理 API 令牌：与 admin 的 management-token（为空则 access-token）一致；生产经 VITE_SCHED_TOKEN 注入
http.defaults.headers.common['X-Access-Token'] = import.meta.env.VITE_SCHED_TOKEN || 'changeme'
http.interceptors.response.use(
  res => {
    const r = res.data
    if (r.code !== 0) return Promise.reject(new Error(r.message || '请求失败'))
    return r.data
  },
  err => Promise.reject(new Error(err.response?.data?.message || err.message || '网络错误'))
)
export const listTasks = () => http.get('/tasks')
export const getTask = id => http.get(`/tasks/${id}`)
// 写操作携带 version 乐观锁；version 来自任务视图，冲突时后端返回 400
export const updateSchedule = (id, d, version) => http.put(`/tasks/${id}/schedule?version=${version}`, d)
export const updateRoute = (id, d, version) => http.put(`/tasks/${id}/route?version=${version}`, d)
export const startTask = (id, version) => http.post(`/tasks/${id}/start?version=${version}`)
export const stopTask = (id, version) => http.post(`/tasks/${id}/stop?version=${version}`)
export const triggerTask = id => http.post(`/tasks/${id}/trigger`)
export const listExecutors = () => http.get('/executors')
export const getLogs = (id, params) => http.get(`/tasks/${id}/logs`, { params })
```

> 权威实现以 `scheduler-console/src/api/scheduler.js` 为准。下文组件片段为说明性示例，与落地工程的差异见 UX 方案 §10。

        </el-select>
        <div v-if="form.routeStrategy==='SHARDING_BROADCAST'" class="help">将触发该服务所有在线实例并行处理</div>
      </el-form-item>
      <el-form-item label="阻塞策略">
        <el-select v-model="form.blockStrategy" style="width:100%">
          <el-option label="串行排队" value="SERIAL" /><el-option label="丢弃本次" value="DISCARD" /><el-option label="覆盖前次" value="OVERRIDE" />
        </el-select>
      </el-form-item>
      <el-form-item label="初始延迟(ms)">
        <el-input-number v-model="form.initialDelay" :min="0" :step="1000" />
      </el-form-item>
    </el-form>
    <template #footer>
      <el-button @click="visible=false">取消</el-button>
      <el-button type="primary" :loading="saving" @click="save">保存并生效</el-button>
    </template>
  </el-dialog>

<script setup>
import { reactive, ref, watch } from 'vue'
import { ElMessage } from 'element-plus'
import { updateSchedule, updateRoute } from '@/api/scheduler'
const props = defineProps({ modelValue: Boolean, task: Object })
const emit = defineEmits(['update:modelValue', 'saved'])
const visible = ref(false), saving = ref(false)
const routes = [
  { v:'FIRST', l:'第一个' },{ v:'LAST', l:'最后一个' },{ v:'ROUND', l:'轮询' },
  { v:'RANDOM', l:'随机' },{ v:'CONSISTENT_HASH', l:'一致性HASH' },
  { v:'FAILOVER', l:'故障转移' },{ v:'SHARDING_BROADCAST', l:'分片广播' }
]
const form = reactive({ type:'CRON', cron:'', fixedRate:60000, fixedDelay:60000, initialDelay:0, routeStrategy:'FAILOVER', blockStrategy:'SERIAL' })
watch(() => props.modelValue, v => { visible.value = v; if (v) fill() })
watch(visible, v => emit('update:modelValue', v))
function fill() {
  const t = props.task || {}
  Object.assign(form, { type:t.scheduleType||'CRON', cron:t.cronExpression||'', fixedRate:t.fixedRate||60000,
    fixedDelay:t.fixedDelay||60000, initialDelay:t.initialDelay||0, routeStrategy:t.routeStrategy||'FAILOVER', blockStrategy:t.blockStrategy||'SERIAL' })
}
async function save() {
  if (form.type==='CRON' && !form.cron?.trim()) return ElMessage.error('请填写 Cron 表达式')
  saving.value = true
  try {
    const updated = await updateSchedule(props.task.taskId, { type:form.type, cron:form.type==='CRON'?form.cron.trim():null,
      fixedRate:form.type==='FIXED_RATE'?form.fixedRate:null, fixedDelay:form.type==='FIXED_DELAY'?form.fixedDelay:null, initialDelay:form.initialDelay }, props.task.version)
    // 周期更新后 version 自增，路由更新须用新 version
    await updateRoute(props.task.taskId, { routeStrategy:form.routeStrategy, blockStrategy:form.blockStrategy, retryCount:props.task.retryCount||0 }, updated.version)
    ElMessage.success('已保存并即时生效（业务服务无感）')
    emit('saved'); visible.value = false
  } catch (e) { ElMessage.error(e.message) } finally { saving.value = false }
}
</script>

## 7. 安全集成

- **accessToken**：admin 与所有 executor 配置同一 `access-token`（建议环境变量注入），注册/心跳/触发/回调双向校验（`TokenInterceptor`）。
- **管理 API 鉴权（已实现，默认开启）**：`ManagementAuthInterceptor` 拦截 `/api/tasks/**`、`/api/executors/**`，校验 `X-Access-Token`。令牌取 `management-token`，为空回退 `access-token`；`management-auth-enabled=false` 或两者皆空才放行（仅限本地开发）。控制台经 `VITE_SCHED_TOKEN` 携带同一令牌。非法/缺失 → 401（40100）。
- **角色级权限（可选扩展）**：当前为令牌级全有全无鉴权；如需按角色控制，可引入 Spring Security 替换/叠加拦截器：
  ```java
  http.authorizeHttpRequests(a -> a.requestMatchers("/api/tasks/**","/api/executors/**").hasRole("ADMIN"));
  ```
- **网络隔离**：执行器端点 `/scheduler-executor/**` 与注册 API 建议仅内网可达。
- 切勿生产匿名放行管理 API 或使用默认 token（`changeme`）。

## 8. 生产部署建议

- admin `auto-ddl=false`，DBA 预建表；`pool-size` 按任务量调整。
- 日志表定期归档清理（按 `trigger_time`）。
- accessToken 用密钥管理，定期轮换（admin/executor 同步）。
- 同服务多实例部署验证路由策略（单跑不重复、分片正确）。
- admin 高可用：设 `ha-enabled=true` 部署主备（已实现 DB 锁选主，须共享同一 DB；leader 宕机自动接管，见设计文档 §9.2）。
- 监控告警：`AlarmNotifier` 已实现，默认 `LogAlarmNotifier`（ERROR 日志）；注册自定义 Bean 即可替换为钉钉/邮件（无在线实例/触发失败时调用）。

## 9. FAQ / 排错

| 现象 | 原因 / 解决 |
|---|---|
| 控制台无任务 | 检查执行器 `enabled`/`admin-addresses`/网络/accessToken；查执行器启动日志注册是否成功 |
| 任务不触发 | 查 DB `enabled`；查该 appName 是否有在线执行器；查 admin 触发日志 |
| 触发失败"无在线执行器" | 执行器未注册或心跳超时下线；检查执行器存活与网络 |
| 集群重复执行 | 路由策略误用 SHARDING_BROADCAST（本就全触发）；单跑请用 FAILOVER/FIRST/ROUND |
| 分片数据重叠 | 业务未按 `id % shardTotal == shardIndex` 过滤；检查 ShardingContext 使用 |
| 改周期不生效 | 确认 PUT code=0；乐观锁冲突刷新重试 |
| 重启后配置丢失 | 确认落库；注册时 DB 有记录不覆盖（设计如此） |
| token 401 | admin 与 executor token 不一致 |
| 管理 API 401（40100） | 控制台 `VITE_SCHED_TOKEN` 与 admin `management-token`（空则 `access-token`）不一致；确认 `management-auth-enabled` 与令牌配置 |
| 写操作 400"缺少参数：version" | start/stop/schedule/route 须携带 `?version=`（取自任务视图） |
| "配置已被他人修改，请刷新后重试" | 乐观锁冲突：他人已改该任务，刷新列表取最新 version 后重试 |
| 执行器端点 404 | 核对 `port` 与 admin 触发地址、防火墙 |
| cron 报错 | 用 Spring 6 位 cron（含秒），不支持 Quartz 7 位 |
| 任务异常后停摆 | JobThread 已隔离异常；检查是否回调失败导致 admin 误判 |
