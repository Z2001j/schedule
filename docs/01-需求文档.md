# 通用定时任务调度系统 · 需求文档（模式二：调度中心 + 执行器）

- 文档编号：REQ-01

- 日期：2026-11-07
- 状态：已实现（M2–M6 完成并经测试/端到端验证）
- 关联：设计文档（DES-02）、开发设计（DEV-05）、开发文档（DOC-06）

## 1. 背景与问题

Java（Spring Boot）项目中定时任务常用 `@Scheduled(cron="...")`，周期硬编码在源码里：改周期要改代码重新发布、无法运行时启停、缺乏可视化、任务散落难治理。

在**微服务**场景下问题进一步放大：

1. **多实例重复执行**：同一服务部署多副本，每个副本都跑 `@Scheduled` → 任务被重复触发。
2. **无统一治理**：任务分散在各服务，没有跨服务的统一清单、控制台与审计。
3. **调度与业务耦合**：调度逻辑和业务代码混在一起，无法集中协调路由、 failover、分片。

## 2. 目标

构建一个**调度与执行分离**的轻量定时任务调度系统，由两个可独立交付的部分组成：

- **调度中心（scheduler-admin）**：独立部署的 Spring Boot 服务，负责任务配置管理、到点触发、执行器注册发现、路由选择、执行日志聚合，并提供 **Vue3 管理控制台**。
- **执行器 SDK（scheduler-executor-starter）**：可复制/自动装配的轻量 starter，嵌入各业务服务。业务方法加 `@ManagedScheduled` 注解即注册为受管任务；执行器接收调度中心触发指令并**本地执行**业务逻辑。

核心价值：

- **加注解即纳管**：业务方仅加注解，执行器自动扫描并向调度中心注册。
- **集中可视化治理**：在调度中心控制台跨服务查询所有任务、改周期、启停、执行一次、看日志，**无需改代码、无需重启业务服务**。
- **集群协调**：调度中心按可配置路由策略选择执行器实例（单跑/轮询/故障转移/分片广播），从根本上解决多实例重复执行。
- **通用可复制**：执行器 SDK 可整体复制进任意 Spring Boot 服务；调度中心独立部署一次、多服务共享。

### 2.1 关键决策（已确认）

| 决策点 | 选择 |
|---|---|
| 架构模式 | 模式二：自研调度中心 + 执行器 SDK（调度与执行分离） |
| 通信方式 | HTTP REST（执行器注册/心跳；调度中心 HTTP 回调触发；执行器回调结果） |
| 集群策略 | 可配置路由策略（FIRST/LAST/ROUND/RANDOM/CONSISTENT_HASH/FAILOVER/SHARDING_BROADCAST） |
| 持久化 | 仅数据库（调度中心侧，配置/注册/日志落库） |
| 前端 | Vue3 + Element Plus 管理控制台（隶属调度中心） |
| 调度类型 | Cron + 固定频率(fixedRate) + 固定延迟(fixedDelay) |

### 2.2 非目标（本期不做）

- 不做 DAG/工作流编排、任务依赖。
- 不做 MapReduce 式动态分片计算（分片广播仅按实例数静态分片）。
- 不做调度中心多活强一致；已实现基于 DB 锁的主备选主（`ha-enabled`，默认单调度中心）。
- 不替代重型批处理平台；定位轻量动态调度。

## 3. 术语

| 术语 | 说明 |
|---|---|
| 调度中心 Admin | 独立服务，管理配置、触发、路由、日志、控制台 |
| 执行器 Executor | 嵌入业务服务的 SDK，注册任务、接收触发、本地执行 |
| 执行器地址 | 执行器实例的 `http://ip:port`，注册到调度中心 |
| 应用名 appName | 业务服务标识，同一 appName 下可有多个执行器实例 |
| 任务 Task | 一个被纳管的方法，唯一 `taskId`，归属某 appName |
| 路由策略 | 调度中心从同 appName 的多个在线实例中选择触发目标的方式 |
| 分片广播 | 触发所有在线实例，携带 shardIndex/shardTotal 供业务并行处理 |
| 阻塞策略 | 任务上次未结束时再次触发的处理：串行/丢弃/覆盖 |

## 5. 功能性需求

### A. 执行器侧（业务服务）

#### FR-01 注解式纳管与自动注册
- 提供 `@ManagedScheduled` 注解（属性：id/name/description/group/type/cron/fixedRate/fixedDelay/initialDelay/enabled）。
- 执行器启动时扫描本服务所有 Bean 的注解方法，构建任务元数据。
- 启动后通过 HTTP 向调度中心**注册**：上报 appName、执行器地址、任务清单（含默认调度配置）。
- `id` 缺省自动生成（`appName:beanName.methodName`），全局唯一稳定。
- 注解周期/启停作为**初始默认值**；调度中心首次无记录时入库，之后以调度中心 DB 为准。

#### FR-02 心跳与下线
- 执行器周期性（默认 30s）向调度中心发送心跳，续约在线状态。
- 调度中心对超时（默认 90s）未心跳的执行器标记下线并从路由池剔除。
- 执行器优雅停机时主动注销。

#### FR-03 接收触发与本地执行
- 执行器暴露内部 HTTP 端点接收调度中心触发指令（taskId、参数、分片信息、logId）。
- 反射调用对应注解方法，**异常隔离**（不影响其他任务与线程）。
- 支持阻塞处理策略（串行排队/丢弃本次/覆盖前次）。
- 执行完成向调度中心**回调结果**（成功/失败、耗时、异常摘要）。

### B. 调度中心侧

#### FR-04 任务清单查询
- 控制台跨服务查询全部受管任务：任务名、所属服务(appName)、分组、调度类型、周期（可读化）、路由策略、启停状态、上次/下次执行时间。
- 支持按 appName/名称关键字/分组/状态过滤（服务端参数化过滤，已实现）；提供详情。

#### FR-05 修改执行周期
- 控制台修改任务调度类型与周期值（cron/fixedRate/fixedDelay/initialDelay）。
- 合法性校验（cron 合法、频率/延迟为正且 ≥ 阈值）。
- 修改即时生效（调度中心重建自身触发计划）并持久化，**无需重启业务服务**。

#### FR-06 启动 / 停止
- 停止：调度中心取消该任务的触发计划，状态置停止并落库。
- 启动：按当前配置重建触发计划。
- 重启调度中心后按 DB 状态恢复（停止的任务不自动运行）。

#### FR-07 手动执行一次
- 控制台对任意任务立即触发一次（按路由策略选执行器），不影响周期计划。
- 返回受理结果，执行结果通过日志/回调体现。

#### FR-08 执行器注册与监控
- 接收执行器注册/心跳，维护在线执行器注册表（appName → 地址列表 → 最后心跳）。
- 控制台展示各 appName 的在线实例数、地址、心跳时间、健康状态。
- 自动剔除超时下线实例。

#### FR-09 路由策略
- 每个任务可配置路由策略：
  - `FIRST`/`LAST`：固定选第一个/最后一个在线实例。
  - `ROUND`：轮询。
  - `RANDOM`：随机。
  - `CONSISTENT_HASH`：按 taskId 一致性哈希选实例。
  - `FAILOVER`：故障转移，优先选空闲（心跳探测）实例，失败顺延下一个。
  - `SHARDING_BROADCAST`：分片广播，触发所有在线实例，携带 shardIndex/shardTotal。
- 无在线实例时触发失败并告警/记录（已实现 `AlarmNotifier` 扩展点，默认日志告警，可替换为邮件/钉钉等）。

#### FR-10 触发与执行日志
- 调度中心到点（CronTrigger/固定频率/延迟）触发任务，经路由选执行器，HTTP 下发。
- 聚合执行器回调结果，记录触发日志：触发时间、目标地址、路由策略、分片、成功/失败、耗时、异常。
- 控制台可按任务查日志；触发失败（无实例/网络异常/执行器拒绝）单独标记。

#### FR-11 持久化
- 任务配置、执行器注册、执行日志存于调度中心数据库。
- 提供建表脚本；可选自动建表。
- DB 为配置权威来源；注解默认值仅首次入库。

### C. 通用与安全

#### FR-12 通用性与可复制
- 执行器 SDK 以独立包 + 自动装配交付，复制源码 + 引依赖即可启用，不绑定业务/ORM。
- 调度中心独立部署，配置项控制：开关、线程池、表名、自动建表、心跳/超时、API 前缀、accessToken。
- 执行器配置项：调度中心地址列表、appName、执行器端口、accessToken、心跳间隔。

#### FR-13 通信安全
- 调度中心与执行器间共享 `accessToken`，触发/注册/心跳/回调请求校验 token，拒绝非法请求。
- 反射调用仅限已注册任务，taskId 必须存在，杜绝任意方法调用。
- 管理控制台 API 纳入鉴权（已实现管理 API 令牌校验 `ManagementAuthInterceptor`，默认开启；可对接项目统一鉴权/Spring Security，不内置后门）。
- cron/数值严格校验，最小周期阈值防刷爆。

## 6. 非功能性需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 低侵入 | 业务方仅加注解 + 引执行器 SDK，无需写调度/注册代码 |
| NFR-02 | 兼容性 | Spring Boot 2.7+/3.x；JDK 8/17+ |
| NFR-03 | 可靠性 | 执行器单任务异常隔离；执行器下线自动剔除；触发失败可重试/告警 |
| NFR-04 | 性能 | 管理操作 < 500ms；触发链路 HTTP 开销可控；调度线程池可配 |
| NFR-05 | 安全 | accessToken 双向校验；管理 API 鉴权；输入校验 |
| NFR-06 | 可维护 | 调度中心/执行器清晰分层；存储/路由面向接口可扩展 |
| NFR-07 | 一致性 | 改周期/启停并发安全（乐观锁）；路由选择不重复（单跑策略） |
| NFR-08 | 可移植 | 执行器 SDK 无业务耦合；包名/表名/路由可配 |
| NFR-09 | 可用性 | 调度中心默认单实例；已实现基于 DB 单行锁 + 心跳的主备选主（`ha-enabled`），leader 宕机自动接管 |
| NFR-10 | 网络容错 | 执行器与调度中心短暂网络抖动不误剔除（心跳宽限）；触发超时可配 |

## 7. 典型用例

### UC-01 新服务接入
1. 业务服务引入执行器 SDK，配置 `scheduler.admin.addresses`、`appName=order-service`、accessToken。
2. 方法加 `@ManagedScheduled(name="订单超时关闭", cron="0 */5 * * * ?")`。
3. 服务启动 → 执行器扫描 → HTTP 注册到调度中心 → 调度中心首次入库默认配置 → 按 cron 触发。
4. 控制台出现 order-service 下该任务，状态运行中。

### UC-02 运维修改周期
1. 控制台找到任务 → 编辑周期改为 `0 */1 * * * ?` → 提交。
2. 调度中心校验 → 持久化 → 重建触发计划。无需重启 order-service。

### UC-03 紧急停止 / 恢复
1. 下游故障 → 控制台停止任务 → 调度中心取消触发。
2. 恢复后启动 → 按配置恢复触发。

### UC-04 集群单跑（故障转移）
1. order-service 部署 3 实例，任务路由策略 `FAILOVER`。
2. 到点调度中心探测空闲实例，选一台触发；该实例宕机则顺延下一台。仅一台执行，无重复。

### UC-05 分片广播批处理
1. 大数据量任务路由策略 `SHARDING_BROADCAST`，order-service 3 实例。
2. 调度中心触发全部 3 实例，分别携带 shardIndex=0/1/2、shardTotal=3。
3. 各实例按 `id % 3 == shardIndex` 处理各自数据，并行不重叠。

### UC-06 手动补跑与日志
1. 控制台"执行一次" → 调度中心立即触发 → 执行器执行并回调。
2. 控制台查日志：触发时间、目标地址、结果、耗时。

### UC-07 复制执行器到新项目
1. 复制执行器 SDK 包 + 注册文件到新服务，引依赖、配调度中心地址与 appName。
2. 加注解即纳管；调度中心控制台自动出现新服务任务。

## 8. 验收标准

- [x] 业务服务加注解启动后，调度中心控制台自动出现任务，周期/状态正确。
- [x] 改周期即时生效且重启调度中心后保留；非法 cron 被拒。
- [x] 停止后不再触发；启动恢复；重启后停止状态保留。
- [x] 执行器注册/心跳正常；超时下线自动剔除；停机主动注销。
- [x] 多实例下各路由策略行为正确（单跑不重复、分片广播携带正确分片）。
- [x] 无在线实例时触发失败并记录/告警。
- [x] 执行器单任务异常不影响其他任务；结果正确回调入库。
- [x] accessToken 校验生效，非法请求被拒（含管理 API 令牌鉴权）。
- [ ] 执行器 SDK 可在两个不同服务复制启用，无需改 SDK 源码。（SDK 已以独立 starter + 自动装配交付并经 demo 验证；待第二个真实业务服务复制实测）
- [x] 并发改周期不产生重复触发计划（乐观锁）。

## 9. 约束与假设

- 调度中心为独立 Spring Boot 服务，具备关系型数据库与 DataSource。
- 执行器嵌入业务服务，业务服务与调度中心网络互通（HTTP）。
- 受管方法为 public 无参（分片信息通过上下文 `ShardingContext` 获取，非方法入参）。
- 默认单调度中心；多调度中心主备通过 `ha-enabled` 启用 DB 锁选主（已实现）。
- 前端控制台基于 Vue3 + Element Plus，可替换栈对接同一 REST 契约。
