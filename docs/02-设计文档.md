## 1. 设计总览

系统代号 **`distributed-scheduled`**，采用**调度与执行分离**架构，由两个独立交付件组成：

| 交付件 | 形态 | 职责 |
|---|---|---|
| **scheduler-admin**（调度中心） | 独立部署的 Spring Boot 服务 + Vue3 控制台 | 配置管理、到点触发、执行器注册发现、路由、日志聚合 |
| **scheduler-executor-starter**（执行器 SDK） | 可复制/自动装配的 starter，嵌入业务服务 | 注解扫描、注册/心跳、接收触发、本地执行、结果回调 |

核心思想：

> **业务服务加注解 → 执行器扫描并 HTTP 注册到调度中心 → 调度中心存配置并到点触发 → 路由选执行器 → HTTP 下发 → 执行器本地执行业务 → 回调结果 → 调度中心记日志。**

与模式一（单服务自治）的根本差异：**周期配置与触发决策全部集中在调度中心**，执行器只是"被触发后本地跑方法"。因此改周期/启停只改调度中心，**业务服务完全无感、无需重启**；集群协调由调度中心统一路由，天然解决多实例重复执行。

### 1.1 设计原则

- **调度集中、执行就地**：调度决策在 admin，业务逻辑仍在归属服务本地执行（不远程耦合业务 API）。
- **DB 为权威**：任务配置以调度中心 DB 为准；注解值仅首次默认。
- **执行器轻量无状态**：执行器不依赖数据库，仅持注解方法句柄 + 与 admin 的 HTTP 通信。
- **异常隔离**：执行器单任务失败不污染线程；admin 触发失败不影响其他任务。
- **可替换**：路由策略、存储、告警面向接口；admin 选主已实现（`ha-enabled`，见 §9.2）。

## 4. 核心机制

### 4.1 执行器注册与发现

- 执行器启动 → `ExecutorRegistrar` 扫描注解方法 → 构建 `JobHandler` 注册到本地 `JobHandlerRegistry`。
- `AdminClient.register()`：POST admin `/api/registry/register`，body：
  ```json
  { "appName":"order-service", "address":"http://10.0.0.1:9999",
    "tasks":[{"taskId":"order-service:orderTask.closeTimeout","name":"订单超时关闭",
              "group":"order","type":"CRON","cron":"0 */5 * * * ?","enabled":true}] }
  ```
- admin `RegistryService`：upsert 执行器节点（appName+address）；对每个任务，DB 无记录则按默认插入 `sched_task`，有记录则忽略（DB 权威）。
- **心跳**：`HeartbeatWorker` 每 30s POST `/api/registry/beat`（appName+address）→ admin 更新 lastHeartbeat。
- **剔除**：admin `RegistryReaper` 定时（每 30s）扫描 lastHeartbeat 超过 90s 的节点标记下线，路由池剔除。
- **注销**：执行器 `@PreDestroy` POST `/api/registry/remove` 主动下线。
- 执行器地址 = `http://{本机IP}:{executor.port}`，端口可配（默认 9999，复用业务服务端口或独立端口）。

### 4.2 调度中心到点触发

- admin `AdminScheduler` 持 `ThreadPoolTaskScheduler`，为每个 enabled 任务建立触发计划：
  - CRON：`CronTrigger`
  - FIXED_RATE：`scheduleAtFixedRate`
  - FIXED_DELAY：`scheduleWithFixedDelay`
- 触发回调 `TriggerService.trigger(taskId, TriggerType.SCHEDULE)`：
  1. 读任务配置 + 该 appName 在线执行器列表。
  2. `ExecutorRouter.route(strategy, nodes, taskId)` 选出目标地址（分片广播返回全部+分片）。
  3. 无在线节点 → 记触发失败日志 + 可选告警。
  4. 生成 logId，`ExecutorClient.run(address, TriggerParam)` HTTP 下发。
  5. 记录触发日志（触发时间、地址、策略、分片、触发结果）。
- 改周期/启停：`TaskService` 更新 DB（乐观锁）→ `AdminScheduler.reschedule()` 取消旧计划建新计划。**执行器无需任何改动**。

### 4.3 执行器接收触发与执行

- `ExecutorController` POST `/scheduler-executor/run`（校验 accessToken）接收 `TriggerParam`：
  ```json
  { "taskId":"...", "logId":123, "params":"...", "shardIndex":0, "shardTotal":1,
    "blockStrategy":"SERIAL", "triggerType":"SCHEDULE" }
  ```
- 按 taskId 找 `JobHandler`，提交到该任务的 `JobThread`（每任务独立线程 + 阻塞队列）：
  - **SERIAL**：排队串行执行。
  - **DISCARD**：若上次未结束，丢弃本次并回调"丢弃"。
  - **OVERRIDE**：中断/覆盖前次，执行本次。
- 执行：设置 `ShardingContext`（ThreadLocal）→ 反射 `method.invoke(bean)` → try/catch 隔离异常。
- 执行完 `AdminClient.callback(logId, success, cost, errorMsg)` 回调 admin 记日志。
- `/scheduler-executor/beat`：空闲探测（FAILOVER 路由用），返回是否 idle。

### 4.4 路由策略

`ExecutorRouter.route(strategy, onlineNodes, taskId)`：

| 策略 | 行为 |
|---|---|
| FIRST | 取列表第一个 |
| LAST | 取列表最后一个 |
| ROUND | 原子计数器轮询（按 taskId 维度） |
| RANDOM | 随机 |
| CONSISTENT_HASH | taskId 哈希环选节点 |
| FAILOVER | 依次 `/beat` 探测，选第一个空闲节点；全忙则取第一个 |
| SHARDING_BROADCAST | 返回全部节点，shardTotal=节点数，shardIndex=序号 |

- 路由面向接口 `RouteStrategyHandler`，可扩展（如按权重、按机房）。
- 单跑策略保证一次触发只选一台 → 集群不重复。

### 4.5 下次执行时间

- admin 侧计算：CRON 用 `CronExpression.next()`；固定频率/延迟估算。停止态为 null。
- 执行器不参与周期计算（周期完全在 admin）。

## 5. 存储设计（调度中心侧）

使用 `JdbcTemplate`，不绑定 ORM。四张表（表名可配；`sched_leader` 仅 HA 启用时建）：

### 5.1 sched_task（任务配置，权威）

| 字段 | 类型 | 说明 |
|---|---|---|
| task_id | VARCHAR(160) PK | 全局唯一（含 appName 前缀） |
| app_name | VARCHAR(64) | 归属服务 |
| task_name / task_group | VARCHAR | 显示名/分组 |
| schedule_type | VARCHAR(16) | CRON/FIXED_RATE/FIXED_DELAY |
| cron_expression | VARCHAR(128) | cron |
| fixed_rate / fixed_delay / initial_delay | BIGINT | ms |
| enabled | TINYINT | 启停 |
| route_strategy | VARCHAR(24) | 路由策略 |
| block_strategy | VARCHAR(16) | SERIAL/DISCARD/OVERRIDE |
| retry_count | INT | 触发失败重试次数 |
| description | VARCHAR(512) | 描述 |
| version | INT | 乐观锁 |
| create_time / update_time | TIMESTAMP | 时间戳 |

### 5.2 sched_executor（执行器注册）

`id`、`app_name`、`address`、`status`(ONLINE/OFFLINE)、`last_heartbeat`、`create_time`。唯一键 (app_name, address)。

### 5.3 sched_task_log（触发/执行日志）

`id`、`task_id`、`trigger_time`、`trigger_type`(SCHEDULE/MANUAL)、`route_strategy`、`executor_address`、`shard_index`、`shard_total`、`trigger_result`、`exec_start`、`exec_end`、`cost_ms`、`success`、`error_msg`。

> 触发日志由 admin 写入（触发时），执行结果由执行器回调后 admin 更新同一条 logId。

### 5.4 sched_leader（HA 选主锁，仅 `ha-enabled=true` 建表）

| 字段 | 类型 | 说明 |
|---|---|---|
| lock_name | VARCHAR(32) PK | 锁名（单行锁，固定值） |
| instance_id | VARCHAR(64) | 当前持锁实例标识 |
| heartbeat | TIMESTAMP | 持锁实例心跳，超时则可被抢占 |

> `AdminLeaderElection` 通过条件 UPDATE 原子续约/抢占该行实现选主，详见 §9.2。

## 6. 通信契约（HTTP REST）

### 6.1 执行器 → 调度中心

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/registry/register` | 注册执行器+任务清单 |
| POST | `/api/registry/beat` | 心跳续约 |
| POST | `/api/registry/remove` | 优雅注销 |
| POST | `/api/log/callback` | 回调执行结果（logId,success,cost,error） |

### 6.2 调度中心 → 执行器

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/scheduler-executor/run` | 下发触发指令 |
| POST | `/scheduler-executor/beat` | 空闲探测（FAILOVER） |

### 6.3 控制台 → 调度中心

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/tasks` | 任务列表（服务端过滤：`appName`/`keyword`/`group`/`enabled`，均可选） |
| GET | `/api/tasks/{id}` | 详情 |
| PUT | `/api/tasks/{id}/schedule` | 改周期 |
| PUT | `/api/tasks/{id}/route` | 改路由/阻塞/重试策略 |
| POST | `/api/tasks/{id}/start` `/stop` `/trigger` | 启停/执行一次 |
| GET | `/api/executors` | 执行器注册表（按 appName） |
| GET | `/api/tasks/{id}/logs` | 执行日志 |

所有跨服务请求携带 `X-Access-Token` 头双向校验。管理 API（`/api/tasks/**`、`/api/executors/**`）另经 `ManagementAuthInterceptor` 令牌校验（默认开启，见 §8）。

**乐观锁契约**：写操作（`schedule`/`route`/`start`/`stop`）须携带查询参数 `?version={当前版本}`，服务端以 `WHERE version=?` 条件更新并自增；版本不符抛 `ScheduleException`（HTTP 400 / 业务码 40000，消息"配置已被他人修改，请刷新后重试"），客户端需刷新后重试。`trigger` 为只读触发，不需 version。

## 7. 自动装配与可复制

### 7.1 执行器 SDK
- `ExecutorAutoConfiguration`，`@ConditionalOnProperty(prefix="scheduler.executor", name="enabled", havingValue="true", matchIfMissing=true)`。
- 注册文件 `AutoConfiguration.imports` / `spring.factories`。
- 配置（prefix=`scheduler.executor`）：enabled、admin-addresses、app-name、port、access-token、heartbeat-interval。
- 复制：拷贝 `com.common.schedule.executor` 包 + 注册文件 → 引依赖 → 配置 → 加注解。

### 7.2 调度中心
- 独立 Spring Boot 应用（`SchedulerAdminApplication` + `AdminBeanConfig` 装配），引入 jdbc + web。
- 配置（prefix=`scheduler.admin`）：enabled、pool-size、table-name/executor-table-name/log-table-name/leader-table-name、auto-ddl、access-token、heartbeat-timeout、reaper-interval、trigger-timeout、min-period-ms、management-auth-enabled、management-token、ha-enabled、election-interval、leader-timeout。
- 前端 Vue3 控制台（scheduler-console）独立工程，`/api` 代理到 admin；或独立前端对接同一 REST 契约。

## 8. 安全设计

- **accessToken**：admin 与 executor 共享密钥，注册/心跳/触发/回调均校验 `X-Access-Token`，防伪造触发与非法注册。
- **任务白名单**：执行器仅执行本地已注册 taskId；admin 仅触发 DB 中存在的任务。
- **管理 API 鉴权（已实现）**：`ManagementAuthInterceptor` 拦截 `/api/tasks/**`、`/api/executors/**`，校验 `X-Access-Token`。`management-auth-enabled` 默认 `true`；令牌取 `management-token`，为空则回退 `accessToken`；两者皆空则放行（仅限本地开发）。非法/缺失令牌返回 401（业务码 40100）。当前为令牌级全有全无鉴权；角色级权限可对接 Spring Security/项目统一鉴权作为扩展。
- **输入校验**：cron 合法性、周期最小阈值、路由策略枚举校验。
- **最小权限**：执行器内部端点 `/scheduler-executor/**` 建议仅内网可达 + token。

## 9. 高可用与扩展点

### 9.1 执行器集群
天然支持：同 appName 多实例注册，admin 路由协调。单跑策略不重复，分片广播并行。

### 9.2 调度中心 HA（已实现）
- 默认单 admin（`scheduler.admin.ha-enabled=false`，恒为 leader）。多 admin 部署时开启 HA，避免重复触发：
  - `AdminLeaderElection` 基于 DB 单行锁表 `sched_leader`（lock_name 主键 + instance_id + heartbeat）+ 心跳选主。
  - 条件 UPDATE 原子续约/抢占：仅当锁属于自己或心跳超时（`leader-timeout`）才成功；并发 INSERT 由主键去重。每个实例周期（`election-interval`）竞选。
  - 仅 leader 实例真正下发到点触发（`AdminScheduler.runScheduled` 判主），follower  standby；leader 宕机后心跳过期，follower 自动接管。手动触发不受判主限制，任意节点可执行。
  - Bean 初始化以 `@DependsOn("schemaInitializer")` 保证建表先于选主；实例退出时释放锁加速接管。
- 多实例须共享同一数据库（如 MySQL，或 H2 `AUTO_SERVER=TRUE` 文件库）。

### 9.3 其他扩展点
- `RouteStrategyHandler`：自定义路由。
- `TaskConfigDao` 等：换存储。
- `AlarmNotifier`：触发失败/无实例告警，已实现，默认 `LogAlarmNotifier`（ERROR 日志）；注册自定义 Bean（`@ConditionalOnMissingBean` 让位）即可替换为钉钉/邮件等。
- 触发链路接入链路追踪/指标。

## 10. 关键时序

### 10.1 注册
```
业务服务启动 → ExecutorRegistrar 扫描注解 → JobHandlerRegistry
 → AdminClient.register(appName,address,tasks) → admin RegistryService
    → upsert sched_executor
    → 每个 task：DB 无则 insert 默认配置 → AdminScheduler 建立触发计划
 → HeartbeatWorker 启动周期心跳
```

### 10.2 到点触发（单跑）
```
AdminScheduler 到点 → TriggerService.trigger(taskId)
 → 读配置 + 在线节点 → Router.route(FAILOVER) → 选 address
 → 生成 logId → 写触发日志 → ExecutorClient.run(address, TriggerParam)
 → 执行器 JobThread 反射执行 → AdminClient.callback(logId,result)
 → admin 更新日志执行结果
```

### 10.3 改周期
```
控制台 PUT /api/tasks/{id}/schedule → TaskService 校验
 → DB update(乐观锁 version+1) → AdminScheduler.reschedule(取消旧/建新)
 → 返回 TaskView（执行器无感）
```

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 执行器异常致任务停摆 | JobThread wrapper 吞异常并回调失败 |
| 网络抖动误剔除执行器 | 心跳宽限期（90s）+ 触发前实时探测 |
| 无在线实例 | 触发失败日志 + 告警 + 可配重试 |
| 并发改周期 | DB 乐观锁 + taskId 级调度锁 |
| 伪造触发/注册 | accessToken 双向校验 + 内网隔离 |
| admin 单点 | DB 锁选主主备（`ha-enabled`，已实现，leader 宕机自动接管） |
| 分片广播实例数变化 | 每次触发按当前在线数动态计算 shardTotal |
| 极小周期刷爆 | 最小周期阈值 + 线程池隔离 + 阻塞策略 |
| 发布重置运维配置 | 注册时 DB 有记录则不覆盖 |
