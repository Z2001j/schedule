# 通用定时任务调度系统 · UX 方案（调度中心控制台）

- 文档编号：UX-04
- 版本：v2.0
- 日期：2026-11-07
- 关联：原型页面（PROTO-03）、开发设计（DEV-05）
- 技术栈：Vue3 + Element Plus（控制台隶属调度中心）

---

## 1. 设计目标

控制台面向运维/平台管理员，是**跨服务集中治理**的统一入口。核心 UX 目标：

1. **全局态势**：跨服务任务清单 + 执行器在线状态，一屏掌握整个系统的调度健康度。
2. **改得放心**：周期/路由编辑有校验、有确认；明确告知"业务服务无感、无需重启"。
3. **集群可见**：路由策略、在线实例、分片信息直观表达，让"集群单跑/分片并行"可理解。
4. **可追溯**：触发与执行结果通过日志抽屉可查，失败原因清晰。
5. **状态真实**：运行/加载/空/错误/无实例五态明确。

## 2. 信息架构

```
定时任务调度中心
├─ 顶部：标题 + 副标题 + 刷新
├─ Tab 导航
│  ├─ 任务管理（默认）
│  │  ├─ 概览卡片：任务总数 / 运行中 / 已停止 / 接入服务数
│  │  ├─ 工具栏：关键字搜索 + 服务筛选 + 状态筛选 + 计数
│  │  └─ 任务表格
│  │     ├─ 列：名称(+ID) / 所属服务 / 类型 / 周期 / 路由策略 / 状态 / 上次执行 / 下次执行 / 操作
│  │     └─ 行操作：编辑 · 停止|启动 · 执行一次 · 日志
│  └─ 执行器监控
│     ├─ 工具栏：服务名/地址搜索 + 心跳说明
│     └─ 执行器表格：appName / 在线实例数 / 地址 / 最后心跳 / 状态
├─ 弹窗：编辑任务（调度类型 + 周期 + 路由策略 + 阻塞策略 + 初始延迟）
└─ 抽屉：执行日志（触发时间/路由/执行器/分片/结果/耗时/异常）
```

## 3. 页面与流程

### 3.1 任务管理（默认视图）

- 进入即加载跨服务任务列表，骨架屏过渡。
- 概览卡片含"接入服务数"，体现微服务全局视角。
- **所属服务列**用紫色标签突出 appName，强化"任务归属哪个服务"。
- **路由策略列**用橙色标签（故障转移/分片广播/轮询…），让集群行为一目了然。
- 周期列：cron 等宽字体；固定频率/延迟可读化（"每 30 秒"/"结束后 120 秒"）。
- 状态：绿=运行中、灰=已停止，颜色+圆点+文字三重编码。
- 上次执行：时间 + ✓成功/✗失败；下次执行停止态显示 `—`。
- 服务筛选下拉动态由当前任务的 appName 去重生成。

### 3.2 编辑任务流程

```
点击"编辑" → 弹窗回填（周期 + 路由策略 + 阻塞策略）
→ 切换调度类型 → 条件表单切换（保留各自输入）
→ 实时校验（cron 合法 / 数值 ≥ 1000ms）
→ 选择路由策略（下拉，含 7 种）+ 阻塞策略（串行/丢弃/覆盖）
→ "保存并生效" → 前端校验 → PUT schedule（+ route）
→ 成功：关闭 + Toast"已保存并即时生效（调度中心已重调度，业务服务无感）" + 刷新行
→ 失败：弹窗内错误，保留输入
```

关键交互：
- **路由策略选择**：下拉项附简短说明（tooltip）。选"分片广播"时提示"将触发该服务所有在线实例并行处理"。
- **阻塞策略**：解释三种语义（串行排队/丢弃本次/覆盖前次），默认串行。
- **无感语义**：按钮"保存并生效" + 成功 Toast 明确"业务服务无感、无需重启"，区别于模式一。

### 3.3 启停流程

- **停止**：确认框"确认停止任务「X」？调度中心将不再触发。" → POST stop → 状态变灰、下次执行 `—`、Toast。
- **启动**：POST start（恢复操作无需确认）→ 状态变绿、Toast。
- 启停只影响调度中心触发计划，执行器无感。

### 3.4 执行一次流程

- 点击"执行一次" → POST trigger → 调度中心按路由选执行器 → Toast 显示触发目标：
  - 单跑策略：`已触发 → http://10.0.0.1:9999`
  - 分片广播：`已触发 → 全部 3 台实例（分片广播）`
  - 无在线实例：红色 Toast `触发失败：该服务无在线执行器`。
- 异步受理，结果通过日志/上次执行体现；不改变启停与周期。

### 3.5 执行日志抽屉

- 点击"日志" → 右侧抽屉滑出，标题含任务名。
- 每条日志卡片：触发时间 + 成功/失败标记；明细：触发类型、路由策略、执行器地址、分片(index/total)、耗时、异常摘要。
- 失败条目异常红字突出；可按时间倒序，支持加载更多（分页）。
- 抽屉 Esc/点击遮罩关闭。

### 3.6 执行器监控

- Tab 切换进入；表格按 appName 分组（rowspan 合并服务名与在线数）。
- 在线实例数 `在线/总数`，在线绿色、全下线灰色。
- 每实例：地址（等宽）、最后心跳时间、在线/下线标签。
- 下线实例（心跳超时）灰显，直观反映集群健康。
- 顶部说明"心跳超时 90s 自动剔除 · 停机主动注销"。

## 4. 交互细节规范

| 场景 | 规范 |
|---|---|
| 操作反馈 | 所有写操作 Toast（成功绿/失败红）+ 行内更新 |
| 按钮 loading | 提交/启停/触发期间 loading 防重复 |
| 防抖 | 搜索 300ms 防抖 |

| 键盘可达 | 弹窗/抽屉 Esc 关闭、焦点陷阱、Tab 循环 |
| 路由策略提示 | 下拉项 tooltip 解释语义，分片广播额外提示 |
| 乐观更新 | 启停可先置中间态，失败回滚 |

## 5. 状态设计

### 5.1 加载态
- 首次：表格骨架屏；刷新：半透明 + 进度条保留旧数据。

### 5.2 空态
- 无任务：图标 + "暂无受管任务，请在业务服务方法上添加 @ManagedScheduled 并接入执行器" + 集成文档链接。
- 筛选无结果："没有匹配的任务" + 清空筛选。
- 执行器空： "暂无执行器注册，请检查业务服务执行器配置与网络"。

### 5.3 错误态
- 列表失败：错误占位 + 重试。
- 写失败：Toast 红 + 后端 message（如"cron 不合法""配置已被他人修改，请刷新"）；弹窗保留输入。

### 5.4 无在线实例态（模式二特有）
- 触发时该 appName 无在线执行器：明确红色提示"无在线执行器"，日志记触发失败。
- 任务行可加警示图标（所属服务全下线时），提示运维关注。

### 5.5 权限态
- 无权限：操作按钮禁用 + tooltip；或整页只读（由 admin 鉴权决定）。
- 实现现状：admin 管理 API 为令牌级鉴权（`ManagementAuthInterceptor`，全有全无），控制台通过 `X-Access-Token` 访问；令牌非法时请求 401。角色级"按钮禁用/整页只读"为扩展方向（对接 Spring Security/项目统一鉴权后按权限渲染），当前未内置。

## 7. 响应式

- ≥1024px：完整表格 + 4 列卡片。
- 768~1024px：卡片 2 列，表格横向滚动，操作列固定右侧。
- <768px：卡片 2 列，工具栏纵向堆叠，抽屉宽度自适应（94vw）。

## 10. 实现现状与差异（scheduler-console）

已交付控制台为本 UX 方案的**可用子集**，核心治理闭环（查任务→改周期/路由→启停→执行一次→查日志→执行器监控）已浏览器联调通过。与上文完整方案的差异：

- **概览卡片**（任务总数/运行中/已停止/接入服务数）未实现；顶部为标题+副标题，刷新按钮在各 Tab 工具栏内。
- **任务表格列**：实际为 名称(+ID)/所属服务/周期/路由策略/状态/在线实例/下次执行/操作；未含独立的"类型""上次执行"列（新增"在线实例"列）。
- **过滤**：工具栏关键字/服务/状态过滤当前为**前端计算过滤**；服务端参数化过滤（含 group）已在 admin 实现，控制台尚未接入 group 筛选与服务端查询。
- **执行器监控**：平铺表格（服务/地址/最后心跳/状态），未做 rowspan 分组与在线计数、搜索框。
- **执行一次 Toast**：未回显路由目标地址/分片（方案 §3.4 为增强项）。
- **日志抽屉**：固定取最近 50 条，未做分页/加载更多。
- **自动刷新**：任务与执行器列表均 10s 轮询。
- **鉴权**：控制台经 `VITE_SCHED_TOKEN`（默认 changeme）携带 `X-Access-Token`；角色级权限态见 §5.5。

> 权威实现以 `scheduler-console/src` 为准；本文档其余章节为完整 UX 目标方案。
